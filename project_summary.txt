1. PROJECT OBJECTIVES & ARCHITECTURE
------------------------------------------------------------------------
Goal: Establish a research-grade waste classification and segmentation
system combining:
* Branch A: Global vision features using the EVA-02 Vision Transformer.
* Branch B: Local geometry and shape features using a Deformable CNN.
* Fusion: Bidirectional Cross-Attention module connecting the branches.
* Multi-Task Heads: Classification MLP + segmentation U-Net decoder.
* Explainability (XAI): Gated Attention Rollout vs. Grad-CAM visualizer.

------------------------------------------------------------------------
2. DATASETS STATUS & SPLITS (VERIFIED & UNIQUE)
------------------------------------------------------------------------
* Stage 1: TrashNet (Classification)
  - Dataset: 6 category folders (cardboard, glass, metal, paper, plastic, trash)
  - Location: data/TrashNet
  - Split: 80% train, 10% val, 10% test (2,527 images total)
* Stage 2: TACO (Object classification + segmentation)
  - Dataset: COCO JSON annotations + image batch folders
  - Location: data/TACO
  - Split: 80% train, 10% val, 10% test (1,500 images total)
* Stage 3: ZeroWaste-f (Semantic Segmentation)
  - Dataset: Labeled video frame splits (train, val, test) + labels/masks
  - Location: data/ZeroWaste
  - Split (Deduplicated):
    - Train: 3,002 images & masks
    - Validation: 572 images & masks
    - Test: 929 images & masks

4. BUG RESOLUTIONS
------------------------------------------------------------------------
The following critical code modifications were implemented to resolve Windows-
and dataset-specific runtime errors:

* Windows Case-Insensitive Globbing Bug:
  - Cause: On Windows, globbing matching patterns like '*.png' and '*.PNG' 
    returns duplicate paths for the same files, doubling the dataset size.
  - Fix: Implemented os.path.normpath + set deduplication inside 
    datasets/zerowaste.py and datasets/trashnet.py.
* ZeroWaste-f Path Adapter Alignment:
  - Cause: ZeroWasteDataset expected root_dir/images/[split] but the real 
    dataset extracts to root_dir/[split]/data.
  - Fix: Updated datasets/zerowaste.py to read directly from split folders 
    data/ZeroWaste/[split]/data and sem_seg.
* SubsetWrapper Dataset Attribute Bug:
  - Cause: SubsetWrapper assumed all inputs are PyTorch Subset splits 
    (with indices and .dataset attributes), throwing AttributeError for raw 
    ZeroWasteDataset objects.
  - Fix: Added a hasattr(subset, 'dataset') fallback check inside 
    datasets/__init__.py to support raw datasets.
